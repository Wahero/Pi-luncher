Get started

快速开始

需要 Rust 工具链与已安装的 Pi Coding Agent（pi、pi-web、npm）。

克隆仓库

源码即项目，无二进制发布渠道。

$git clone https://github.com/Wahero/Pi-luncher.git

构建发布版

体积优化已内置，产物约 390 KB。

$cargo build --release

运行

直接跑，或先安装 ~/.cargo/bin。

$.\target\release\pi-launcher.exe
Pipeline

五个步骤，各自有退出码

失败精确挂点（1–5 号码），日志直达该步骤的错误路径。

环境预检

pi / pi-web / npm 逐个探测；缺命令直接终止。

exit 1

更新 Pi

pi update --all，失败打 stderr 摘要。

exit 2

升级 pi-web

npm view 对比；运行中或被锁则按现版继续。

exit 3

启动 pi-web

detached + HTTP 就绪探测（真实比例，60s 上限）。

exit 4

进入 Pi CLI

前台交互；quiet 模式自动跳过。

exit 5
Modes

两种日常模式 + 一个可选开关

正常模式

pi-launcher

动画进度 + Pi CLI 交互 + 结束停留。

  • 按 Enter 立即关窗
  • 30 秒无输入自动倒计时关闭
  • 非交互终端退化为纯文字
安静模式

--quiet · -q · --auto

计划任务与开机自启场景。

  • 近零输出，仅提示日志路径
  • 跳过 Pi CLI；supervisor 照常
  • 成功 / 失败都自动关窗
可选开关

--spin <名字>

固定右侧动画；默认按启动次数在 6 组池中轮换。

  • -h / --help 显示用法
  • --force-tty 调试渲染路径

Logging

两种模式都落盘的全程日志

计划任务的例外保险：窗口关了，证据还在。

  • №每次启动新文件自动保留最近 20 份，旧文件清理
  • 会UTF-8 带 BOMPowerShell / 记事本正确打开

Exit codes

计划任务读得懂的 0–5

0全部成功
1环境预检失败
2pi update 失败
3pi-web 检查 / 升级失败
4pi-web 启动失败
5Pi CLI 异常
ⓘ

容错策略已内置：pi-web 正在运行 → 跳过升级、按现版继续；升级撞文件锁（EBUSY）→ 警告后继续；真正升级失败才退出码 3。另外自带 supervisor：pi-web 崩溃自动重启（最多 3 次）。

项目结构

pi-launcher/ ├── Cargo.toml # 依赖 + [profile.release] 体积优化 ├── src/ │ ├── main.rs # 编排 / supervisor / 30 秒关窗 │ ├── ui.rs # 统一输出层 + 文字日志 │ ├── steps.rs # 1-5 号步骤 │ └── command_runner.rs # 探测 / detached 启动 ├── tools/gen-docs.ps1 # 文档再生成 ├── docs/Pi-Luncher.html # 设计说明（v1.0 同步） └── README.md

四条设计决定

  • 输出全部走 ui.rs同一份步骤逻辑在动画终端 / CI / 计划任务三种环境下行为一致，安静态零输出但日志照写。
  • 不伪造进度npm 的内情不可见，只显示「已耗时 + 转圈」；唯一确定时长（就绪等待 60s）才给真实比例。
  • CLI 前清掉进度条Pi CLI 是全屏 TUI，残留 bar 会打架；清完之后 supervisor 消息降级为普通打印。
  • supervisor 两种模式都在quiet 时没有人盯窗口，pi-web 照样可能崩，守护不随渲染模式变化。
