Scope

改的是终端里那块画面，流程一行代码不动

改造范围仅限输出层模板：五步流程、退出码 0–5、日志、supervisor 全不变。 以下每张卡＝80 列等宽模拟（网格排，CJK 宽差不影响对齐）， 颜色用 Windows Terminal 默认色板，spinner 是真实帧动画。 v1.1.1 已实装 ——三档全部落地，由 --display 参数切换，预设 A。

新增参数 · 已实装（v1.1.1）

--display <A|B|C>：显示模式，三档各成一体

不再是三选一的提案，而是运行参数。同一套行凝固引擎，六张行模板 + 三张开场按档切换。

cmd — 参数行为实录─ ▢ ✕
$ pi-launcher --display b
（以 B 轻修版式运行，开场为圆角细框）
$ pi-launcher --display ledger
（别名等效，即 A 工作账）
$ pi-launcher --display x
未知显示模式 'x'（--display 可选 A|B|C，即 ledger|lite|min）
（print 后退出码 1，流程不启动）
规格

参数细则

  • 取值：A|B|C（大小写不敏感）；别名 a/b/c、ledger/lite/min。
  • 预设：不给参数即 A 工作账。
  • 非法值：列出可选项后退出码 1，流程不启动。
  • 边界：--quiet 与非终端（管道/CI）下无效——退化为既有纯文字/零输出路径，与显示模式无关。
  • 实现落点：ui.rs（Display 枚举 + 模板 + 重放）与 main.rs（解析 + 开场）；steps.rs 仅传行内短名。

痛点
  • 1大 banner 占 4 行，标题信息一行业能放下，其余是装饰性重复。
  • 2「将依次执行」7 行全是预告——步骤自己会报状态，预告行等流程跑完就作废。
  • 3一步用 2–3 行：header 行 + 进度行 + 完成行；5 步流程被撑到 30+ 行，真正的工作密度被稀释。
  • 4符号混载：✓ 承担「就绪/更新完/启动完」三种语义，失败时 stderr 直接砸屏幕，没有统一层级。
模式 A · 预设 · 已实装

工作账 Ledger：一步一行，行即事实

每个步骤只有一行：进行中实时刷新（spinner / 进度条 + elapsed + 当前动作）， 完成后在原位凝固为 ✓ + 结论。信息只增不改位置，视线不需要回跳。 v1.1.1 起这就是默认画面；行只在所属步骤开始时出现，不预占空行。

Rust 端怎么落的

  • 行凝固引擎：在 ui.rs——每步一行挂在 MultiProgress 上，用 insert(idx-1) 把步骤行插到整体条上方，整体条钉死屏幕底部；完成瞬间该行原位换成静态 ✓/✗ 文本并停刷（URL 等结论并入结论列）。
  • 收尾重放：成功路径 replay_ledger() 先撤场全部渲染，再按序把凝固行重放为普通行——日志路径与「✓ 全部步骤完成」自然排在账目之后。
  • 列宽纪律：编码+名称整体 25 列（A）/26（B）/10（C），unicode-width 补位；非 TTY 自动退化为逐行打印，quiet 零输出不受影响。
  • 体积：实测 408,064 bytes（基线 399,360 → +2.2%，新基线已记入 AGENTS.md）。

Rust 端怎么落的

  • 与 A 共引擎：同一个行凝固引擎，仅换模板字符串与开场三件（圆角框 + 信息行 + 空行）——ProgressStyle 梳式差异，风险与 A 一致。
  • 非 TTY / 计划任务：退化路径三档共用，零回归；quiet 照旧零输出。
  • 行数预算：约 10 行（框 3 + 信息 1 + 已发生步骤 1 行/步 + 整体 1）。

Rust 端怎么落的

  • 共用引擎的第三张皮：行模板收窄到 10 列（短名 + 状态 + 耗时）、开场仅 1 行标题；整体条也收窄（16 格）。

Common · 三档通吃

四个符号 + 六种色，不再有第五种

v2 规定符号只承载「状态」这一个语义维度，颜色只用 Windows Terminal 默认色板——不引入 emoji，任何 Windows 终端（含 conhost）渲染一致。

✓
成功

步骤完成 / 子项就绪。唯一绿色。

✗
失败

真失败才用。出现即注定退出码 1–5。

⚠
容忍

EBUSY / 运行中跳过升级等「降级继续」。

进行中

动画帧右侧恒定挂 elapsed 计时。
